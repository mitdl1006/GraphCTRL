# GraphCTRL

설비·라인에 장착되는 로봇(첫 대상: Universal Robots e-Series)의 동작을 3D 작업공간에서 스케치하고, 치수·구속조건을
넣고, 경로를 자동으로 계획해 보는 데스크톱 프로그램입니다. 전부 Rust로 작성하며 화면은 egui + wgpu를 씁니다.

아직 개발 초기입니다. 지금 되는 것:

- **스케치**: 원점 평면에 2D 스케치(선·원·호·사각형), 구속조건 12종, 치수(`25 mm`, `폭 * 2` 같은 수식, 더블클릭으로 수정),
  브라우저의 파라미터 표(이름 = 값, 치수 수식에서 사용), 드래그,
  과구속 시 참조 치수 전환, 실행 취소/다시 실행, 저장/열기(`.gctrl`).
- **3D 스케치**: "3D 모델" 탭의 "3D 스케치" → 선 도구로 공간에 폴리라인(기존 점에 붙기, 직전 점을 지나는 X/Y/Z 축에
  잠기기, 그 밖에는 작업 평면 위 — Tab으로 XY/YZ/ZX 전환), 길이·높이 치수, X/Y/Z 방향·평면 위 구속.
- **로봇 셀**: 리본의 "로봇" 탭에서 UR5e(또는 샘플 6축 로봇) 추가, 또는 "URDF 불러오기"로 다른 로봇의 `.urdf`
  파일 추가(메시는 URDF가 있는 폴더 주변에서 찾음, STL·COLLADA) → 오른쪽 패널의 슬라이더로 조그(충돌하면 붉게 표시), 로봇 베이스 위치와 툴 중심점(TCP) 오프셋 입력 → "현재 자세"로
  웨이포인트 추가(스케치에서 점 하나를 선택하고 "스케치 점"을 누르면 그 점을 따라다니는 웨이포인트) → 상자·원기둥·구
  장애물 추가와 배치, "메시 불러오기"로 설비 STL 추가(mm 단위 파일은 자동으로 m로 환산) → "경로 만들기" → 웨이포인트별로 자유 이동/직선 이동(LIN) 선택 → 플래너 선택(RRT-Connect, RRT, RRT*, Informed RRT*, PRM) → "계획" → "재생".
  장애물이나 스케치 치수를 바꾸면 경로가 "오래됨"으로 표시됩니다.
- **작업 좌표계**: 스케치에서 점을 하나 만들고 치수·고정 구속으로 완전히 구속한 뒤, 그 점을 선택하고 로봇 탭의
  "좌표계"를 누르면 그 점이 원점인 좌표계가 생깁니다. 점을 Ctrl+클릭으로 순서대로 2~3개 고르면 로봇 컨트롤러의 3점
  사용자 좌표계처럼 원점 → X축 방향 점 → XY 평면 위 점(+Y 쪽)으로 축 방향까지 정해집니다(점이 하나면 스케치 축, 둘이면
  Z는 스케치 법선). 패널에서 축 점을 바꾸거나 R/P/Y로 더 돌릴 수 있고, 좌표계의 6축 값(X, Y, Z, R, P, Y와 UR 회전 벡터)이
  월드 기준·로봇 베이스 기준으로 표시됩니다. "좌표계 기준"은 로봇의
  현재 TCP 자세를 그 좌표계 기준으로 저장하고, 패널에서 좌표계 기준 위치·자세를 숫자로 고칠 수 있습니다. 원점 치수를
  바꾸면 그 좌표계 기준의 웨이포인트와 경로가 모두 따라 움직입니다(경로는 "오래됨" → 다시 계획).
- **스케치 → 경로**: 스케치(2D·3D)의 선을 그린 뒤 로봇 탭의 "스케치 경로"를 누르면 선의 끝점들이 웨이포인트가 되고
  각 선이 직선 이동이 됩니다. 스케치 치수를 고치면 경로가 "오래됨"이 되고, 다시 계획하면 새 형상을 따라갑니다.
- **표시/투명도**: 브라우저에서 설비(바디)와 로봇 앞의 체크박스로 보이기/숨기기, 패널의 바디 항목과 조그 위의
  "투명도" 슬라이더로 0~95 % 투명하게 할 수 있습니다. 표시만 바뀌고, 숨기거나 투명한 설비도 경로 계획에서는 계속
  장애물입니다. 설정은 프로젝트에 저장됩니다.
- **프로젝트 저장/열기**: 파일 메뉴(Ctrl+S, Ctrl+Shift+S는 다른 이름으로, Ctrl+O, Ctrl+N). `이름.gctrl` 옆에 `이름_files`
  폴더가 생기고, 불러온 설비 메시와 URDF 로봇의 메시 파일이 그 안에 복사됩니다. 파일은 그 폴더를 상대 경로로 가리키므로
  `.gctrl` 파일과 `_files` 폴더를 함께 옮기면 다른 PC에서도 그대로 열립니다. 파일 메뉴의 "최근 프로젝트"에 최근 8개가
  남고, 저장하지 않은 작업은 1분마다 자동 저장되어 프로그램이 비정상 종료되면 다음 실행 때 복구할지 묻습니다
  (Windows `%APPDATA%\GraphCTRL`, Linux `~/.config/graphctrl`).
- **뷰 조작(Inventor 방식)**: 휠 = 줌, 가운데 드래그 = 팬, Shift + 가운데 드래그 또는 F4 + 왼쪽 드래그 = 오빗, F6 = 홈.

계획은 [docs/PLAN.md](docs/PLAN.md), 진행 상태는 [docs/STATUS.md](docs/STATUS.md), 화면 캡처는
[docs/evidence/stage-4.md](docs/evidence/stage-4.md)에 있습니다.

## 빌드와 실행

필요한 것: [rustup](https://rustup.rs). Rust 버전은 `rust-toolchain.toml`에 고정되어 있어 처음 실행할 때 자동으로
설치됩니다. Windows는 Visual Studio Build Tools(“C++를 사용한 데스크톱 개발”)가 필요합니다.

```bash
cargo run -p graphctrl
```

첫 빌드는 의존성 약 470개를 컴파일하므로 몇 분 걸립니다. 두 번째부터는 바뀐 부분만 다시 컴파일합니다.

### 빌드 중 메모리 부족 오류가 날 때

`rustc-LLVM ERROR: out of memory`나 `memory allocation of ... bytes failed`가 나오면 코드 문제가 아니라 컴파일러가
쓸 메모리가 모자란 것입니다. cargo는 논리 프로세서 수만큼 크레이트를 동시에 컴파일하는데, 동시 개수를 줄이면 됩니다.
이미 끝난 크레이트는 다시 컴파일하지 않습니다.

```bash
cargo run -p graphctrl -j 2
```

매번 붙이기 번거로우면 환경 변수로 정해 둘 수 있습니다(PowerShell).

```powershell
$env:CARGO_BUILD_JOBS = "2"
```

숫자가 작을수록 메모리를 덜 쓰고 빌드는 느려집니다. 최적화 수준을 낮추는 것으로는 해결되지 않습니다(크레이트당 컴파일러
메모리가 거의 같음, 측정값은 [docs/evidence/stage-0.md](docs/evidence/stage-0.md)).

## 개발

커밋 전에 다음 한 줄이 통과해야 합니다. 포맷, `cargo check`, clippy(Linux와 Windows 대상), 테스트, GPU 테스트,
레이어 검사, 라이선스 검사를 순서대로 돌립니다.

```bash
cargo xtask gate
```

| 명령 | 하는 일 |
|---|---|
| `cargo xtask check-layers` | 크레이트 의존 방향이 `layers.toml`의 레이어 순서를 지키는지 검사 |
| `cargo xtask check-licences` | 모든 의존성의 라이선스와 출처가 `licences.toml` 정책에 맞는지 검사 |
| `cargo xtask test-gpu` | GPU가 반드시 있어야 하는 조건으로 테스트 실행(소프트웨어 렌더러가 있으면 그것을 사용) |

작업 규칙은 [CLAUDE.md](CLAUDE.md)에 있습니다.
