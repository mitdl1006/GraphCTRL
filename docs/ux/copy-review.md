# UI 문구 검토 (한국어)

대상: `crates/foundation/gc_i18n/src/lib.rs`의 `Msg` 표. 이 문서는 제안만 적는다. 코드 반영은 리드가 한다.

검토 기준
- 용어 통일: 같은 뜻에는 같은 말. "좌표계"(프레임), "기준 좌표계", "웨이포인트", "플래너", "직선 이동(LIN)", "구속", "치수".
- 어순 통일: 기준은 "기준 좌표계"처럼 명사형으로 쓰고, 버튼은 동사형("~ 추가", "~ 만들기")으로 맞춘다.
- 길이: 상태바·버튼에 들어가는 문구는 한 줄(약 25자 이내)을 목표로 한다.
- 말투: 버튼은 명사·동사 원형, 안내 문구는 "~을 클릭", 알림은 "~했습니다"로 맞춘다.

## 2. 그대로 두어도 되는 것 (확인함)

- 오류·알림의 존댓말: "~습니다"(ErrRedundant, FileSaved 등)와 질문형 "~할까요?"(AskReference, AskSaveChanges)가 일관됨.
- 구속 이름(일치, 수평, 수직, 평행, 직각, 접선 등)과 상태 문구("완전 구속", "N개 치수 필요")는 맞음.
- 좌표계 축 용어 "X축 방향 점", "XY 평면 위 점(+Y 쪽)"은 명확함.
- "월드"와 "로봇 베이스"는 전체에서 같은 뜻으로 쓰임(RefWorld, RefBase, PropPoseWorld, PropPoseBase).

## 3. 영어 문구 (참고)

- MenuLicences: "Licences"(영국식) → "Licenses"(미국식). 앱 전체 영어 표기를 미국식으로 쓴다면 같이 바꾼다.
- CmdCompare: "Compare Planners"와 맞추려면 ko 제안(플래너 비교)과 함께 바꾼다.

## 4. 메모

- 리본 버튼은 폭이 좁다. 동사형으로 바꾸는 항목(현재 자세 추가, 좌표계 만들기 등)은 리본에서 줄바꿈이 생기는지 확인한다.
- 이 표의 제안은 문구만 다룬다. 키 이름과 `Msg` 구조는 바꾸지 않는다.
