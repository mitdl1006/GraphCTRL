# 계획 대비 변경 기록

허용오차·기대값·범위를 바꿀 때 이전 값, 새 값, 근거를 남긴다.

## 2026-11-16 — Stage 1의 "나머지 크레이트 공개 타입 동결"을 하지 않음

- 이전: Stage 1에서 모든 크레이트의 공개 타입·트레잇 시그니처를 본문 없이 먼저 커밋한다.
- 변경: foundation과 api 크레이트만 확정하고, 나머지는 각 크레이트를 구현할 때 확정한다.
- 근거: 동결은 여러 구현 에이전트가 동시에 작업할 때 서로의 인터페이스를 건드리지 않게 하려는 장치였다. 지금은 한 흐름으로 순차 구현하므로 미리 고정하면 추측으로 쓴 시그니처를 다시 고치는 일만 늘어난다. 플러그인 경계(api 크레이트 2개)는 계획대로 확정했다.

## 2026-11-16 — 구현 순서를 스케치 우선으로 변경

- 이전: Stage 2a에서 솔버·로봇·플래너·궤적·카메라·문서를 함께 진행.
- 변경: 스케치 쪽(솔버 → 스케치 → 문서 → 도구 → 뷰포트 → UI)을 먼저 화면에 보이는 데까지 완성하고, 로봇·경로 계획을 그다음에 붙인다.
- 근거: 사용자가 가장 먼저 요청한 것이 "UI, 스케치, 치수·구속조건"이며, 화면으로 확인할 수 있는 결과를 빨리 내기 위해서다. 범위와 게이트는 그대로다.

## 2026-11-17 — 첫 타이머는 "웨이포인트마다 정지하는 동기 사다리꼴"

- 이전: 다점 경로는 블렌드로 C² 경로를 만들고 TOPP-RA로 시간 매개변수화한다(P1).
- 변경: 우선 세그먼트별 동기 사다리꼴(정점에서 정지)만 구현했다. 블렌드 + TOPP-RA는 화면에 경로가 보이는 단계 뒤로 미룬다.
- 근거: 계획 5.9의 대비책과 같은 구성이며, 계획·검증·표시의 세로 조각을 먼저 끝내기 위해서다. 결과적으로 장애물을 돌아가는 경로의 예상 시간은 실제보다 길게 나온다(정점마다 멈추므로).

## 2026-11-17 — 계획 여유(margin)를 검사 간격에 묶음

- 이전: 엣지 검사 간격을 링크별 스윕 상계로 정하고 `δ ≤ 2·pad_min` 불변식으로 보증한다.
- 변경: 플래너는 "요구 패딩 + 검사 한 스텝 동안 링크가 움직일 수 있는 거리(검사 간격 × 팔 길이)"로 검사하고, 최종 궤적은 요구 패딩만으로 4 ms 간격 재검증한다. 좁은 셀에서는 검사 간격을 1/4, 1/16로 줄여 여유도 같이 줄인다.
- 근거: 여유 없이 계획하면 숏컷된 경로가 패딩 경계를 스치면서 검사점 사이에서 패딩을 침범하는 것을 최종 검증이 실제로 잡아냈다. 링크별 스윕 상계는 아직 계산하지 않으므로 보증 문구(`Guarantee`)는 붙이지 않는다.

## 2026-11-17 — 플래너를 아직 플러그인 API로 감싸지 않음

- 이전: `gc_motion`은 플래너를 `MotionPlanner` 트레잇 객체로만 호출하고, 내장 플래너는 `gc_plugin_planners`가 등록한다.
- 변경: 지금은 `gc_motion`이 `gc_plan`을 직접 호출하고, 경로 문서에는 플래너 id 문자열(`rrt_connect` 등)만 저장한다. (계획 자체는 같은 날 작업 스레드로 옮겼다: 앱에서는 `gc_jobs` 스레드에서 돌고 취소할 수 있다.)
- 근거: 로봇·경로가 화면에 보이는 세로 조각을 먼저 끝내기 위해서다. 문서에는 id만 들어가므로 나중에 레지스트리 조회로 바꿔도 파일 형식은 그대로다.

## 2026-11-17 — UR5e 기술 파일을 `gen-ur` 없이 먼저 넣음

- 이전: `cargo xtask gen-ur`가 공식 YAML 4종에서 UR3e/5e/10e/16e URDF를 결정적으로 생성하고, STL은 `gc_plugin_mesh`(mesh-loader)가 읽는다.
- 변경: UR5e 하나만, 검증된 기구학 픽스처에 `visual_parameters.yaml`의 메시 오프셋을 붙인 URDF(`assets/ur/urdf/ur5e.urdf`)를 커밋했다. STL은 `gc_mesh::stl`의 자체 리더로 읽는다(의존성 없음).
- 근거: 사용자의 첫 대상인 UR을 화면에서 계획·재생까지 먼저 확인하기 위해서다. 메시 배치는 테스트가 기하로 검증한다. 나머지 기종과 생성기는 그대로 할 일로 남는다.

## 2026-11-17 — UR5e 시각 메시(DAE)를 P1으로 당김

- 이전: 로봇은 충돌 STL로 표시하고, 시각 메시(DAE)는 P2.
- 변경: 사용자 요청으로 UR5e를 제조사 시각 메시로 그린다. DAE 7개(9.3 MB, BSD-3-Clause)를 `assets/ur/meshes/ur5e/visual/`에 커밋하고 `SOURCES.toml`에 출처·해시를 적었다. `gc_mesh`가 `roxmltree`로 COLLADA를 직접 읽는다(다른 URDF의 `.dae`도 같은 경로로 읽힌다).
- 영향: 저장소와 실행 파일이 약 9 MB 커진다.

## 2026-11-17 — 블렌드 + TOPP-RA 구현(위 "첫 타이머" 항목의 후속)

- 경로에 모서리가 있으면 포물선 블렌드(관절 공간 편차 0.1 rad 이내, 이웃 구간의 절반까지)로 둥글리고 TOPP-RA(격자 약 300구간, 블렌드는 구간당 24칸 이상)로 시간을 매긴다. 블렌드는 계획 여유를 둔 검사기로, 완성된 궤적은 요구 패딩으로 4 ms 간격 재검증한다. 블렌드가 충돌하면 반으로 줄이기를 4번 하고 그래도 안 되면 그 모서리에서 정지한다. 재검증에 실패하면 "웨이포인트마다 정지"로 되돌아간다.
- 계획과 다른 점: TOPP-RA의 제약은 관절 속도·가속도뿐이다(TCP 속도 상한 행 없음). 직선 이동의 TCP 속도 상한은 완성된 궤적을 고르게 늦추는 방식으로 지킨다(`Trajectory::slowed`, 경로별 설정). 직선 한 구간짜리 이동은 닫힌 형태의 사다리꼴을 그대로 쓴다(TOPP-RA 결과는 그 값의 0.5% 이내임을 테스트로 확인).
- 블렌드 구간에서는 격자 사이의 방향 변화를 흡수하려고 한계를 0.95배로 잡는다.


## UR 해석적 IK: Hawkins 포팅 대신 자체 유도

- 계획(5.6): Hawkins `ur_kin.cpp`(BSD-3)를 포팅·보강.
- 실제: `crates/plugins/gc_plugin_ur/src/ik.rs`에 표준 DH에서 직접 유도한 해를 구현했다(θ1은 손목점의 어깨 평면 오프셋,
  θ5·θ6·θ2+θ3+θ4는 `A1⁻¹T` 회전의 Z-Y-Z 분해, θ2·θ3는 평면 2링크). 원본 코드를 쓰지 않았으므로 BSD-3 고지가 필요 없다.
  모든 해는 FK로 검증하고(1e-6), 기종은 체인의 FK를 네 기종의 공개 DH 표와 비교해 판정한다(1e-9 Exact, 5 mm·0.5° NearNominal).
  계획서 부록 D의 기준 자세에서 해 8개·분기 8개를 테스트로 확인했다.

## UR3e wrist_3: 연속 관절 대신 ±360°

- 공식 설명에서 UR3e의 wrist_3는 위치 한계가 없다. 생성한 URDF는 다른 관절과 같은 revolute ±2π로 두었다(플래너가
  상자형 관절 공간만 다루는 지금 구조에 맞춤). 실제 컨트롤러보다 좁은 범위만 쓴다.

## 로봇은 실행 파일 밖의 로봇 라이브러리(`robots/`)에

- 계획(5.6): UR 패키지(URDF·메시·프로파일)를 `gc_plugin_ur`에 넣어 플러그인 제공자로 노출.
- 변경(사용자 요청): 로봇은 애드온처럼 실행 파일과 분리된 `robots/<패키지>/` 폴더에 둔다. 패키지는 `robot.json`(이름·제조사·
  설명 파일·도달 거리·가반 하중·라이선스)과 URDF, `meshes/visual`·`meshes/collision`, 라이선스 파일로 이루어진다. 실행 파일에는
  로봇 데이터가 없다(이전에 `include_bytes!`로 넣던 UR5e 메시 9.3 MB 포함 제거). UR3e·UR10e·UR16e 시각 메시도 같은 커밋에서
  받아 넣었고(`robots/SOURCES.toml`에 출처·해시), UR16e는 UR10e와 공유하는 부품을 자기 패키지에 복사해 둔다.
- 문서에는 라이브러리 로봇의 리소스 폴더를 `library://<패키지>`로 저장하고 열 때 그 PC의 라이브러리 위치로 푼다. 프로젝트
  저장 시 이 로봇의 메시는 복사하지 않는다.
- 라이브러리 폴더는 `RunOptions::robot_dir`, 없으면 작업 폴더·실행 파일 폴더와 그 위 네 단계에서 `robots/`를 찾는다.
- `gc_plugin_ur`는 해석적 IK만 등록한다. 기종 표도 없앴다: 체인의 FK에 DH 길이 6개를 최소제곱으로 맞춰(관절각을 고정하면 손끝
  위치가 길이에 선형) UR형 팔이면 해석적 IK를 붙인다. 사용자가 불러온 UR형 URDF도 해당된다.
- 위 두 항목(UR5e만 커밋, UR5e 시각 메시 커밋)의 경로 `assets/ur/urdf`, `assets/ur/meshes`는 `robots/`로 옮겨졌다.
  URDF 생성 스크립트는 `tools/gen_ur_urdf.py`(입력: `assets/ur/config`).
